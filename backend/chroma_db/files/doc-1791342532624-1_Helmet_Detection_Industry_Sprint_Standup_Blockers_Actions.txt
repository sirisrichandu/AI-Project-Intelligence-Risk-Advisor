HELMET DETECTION & NUMBER PLATE STORAGE SYSTEM
INDUSTRY-LEVEL SPRINT 04 STAND-UP / DELIVERY NOTES
Document Type: Project Execution Notes for AI Project Intelligence & Risk Advisor Testing
Date: 15 October 2026
Project Phase: Model Validation, OCR Integration, API Integration & Release Readiness

1. PROJECT OBJECTIVE
The team is developing a computer-vision system that detects helmet compliance from traffic
imagery/video and, where applicable, detects vehicle/number-plate information using OCR.
The system must preserve traceable evidence and clearly separate confirmed results from
low-confidence results requiring human review.

2. CURRENT DELIVERY STATUS
Overall status: AMBER
Current focus:
- Improve robustness of helmet detection in difficult environmental conditions.
- Improve number-plate OCR accuracy.
- Finalize frontend/backend inference API contract.
- Validate evidence persistence and duplicate-prevention behavior.
- Prepare end-to-end release-readiness testing.

3. BLOCKERS
BLOCKER B-01 — ADVERSE-CONDITION DATASET COVERAGE
Owner: ML Lead
Status: OPEN
The current validation dataset has insufficient coverage of night scenes, rain, glare,
motion blur, and partial occlusion. The team cannot make a reliable release decision
until representative samples are added and evaluated.
Impact: High
Required resolution: Expand the validation dataset and publish scenario-level metrics.
Target date: 12 October 2026.

BLOCKER B-02 — OCR ACCURACY BELOW ACCEPTANCE THRESHOLD
Owner: OCR Engineer
Status: OPEN
Number-plate OCR is inconsistent for blurred, skewed, small, and poorly illuminated plates.
This blocks final evidence-quality approval.
Impact: High
Required resolution: Improve preprocessing, plate cropping, confidence thresholds, and
fallback/manual-review behavior.
Target date: 15 October 2026.

BLOCKER B-03 — INFERENCE API CONTRACT NOT FINALIZED
Owner: Backend Lead
Status: OPEN
The frontend and backend teams have not finalized the versioned request/response contract.
Integration testing is therefore blocked because field names, confidence values, evidence IDs,
and error responses are still subject to change.
Impact: High
Required resolution: Publish the API schema, sample payloads, error model, and obtain
frontend/backend sign-off.
Target date: 10 October 2026.

5. DECISIONS MADE
D-01: YOLOv8 will be used as the baseline object-detection approach.
D-02: Model acceptance will be based on validation performance, not model size alone.
D-03: Precision, recall, mAP, scenario-level errors, and false-positive/false-negative analysis
      must be reported before release approval.
D-04: Helmet status and OCR results with insufficient confidence must be routed to human review.
D-05: Evidence records must have traceable identifiers and timestamps.
D-06: Repeated client requests must not create duplicate evidence records.
D-07: Production deployment requires security, privacy, and evidence-retention approval.
